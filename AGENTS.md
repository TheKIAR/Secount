# Secount — engineering session rules

Secount is a personal cross-platform software product built with Kotlin + Compose Multiplatform.

## Mandatory rule for changes

Whenever a code, UI, logic, workflow, or documentation change is requested:

1. Inspect the current repository state before editing.
2. Keep a running checklist of completed and remaining work.
3. Make the smallest safe change that advances the requested goal.
4. Run the strongest available automated validation before declaring the work complete.
5. Commit every logical change with a focused commit message.
6. Never claim a physical-device or clean-machine test unless it was actually performed.
7. Keep generated build output out of source control. Release artifacts belong in CI/GitHub Releases, not in the repository tree.

## Build expectations

When a local build environment is available, validate:

- Shared tests: `gradle -p android :shared:desktopTest`
- Android release: `gradle -p android :androidApp:assembleRelease`
- Desktop packaging: `gradle -p android :desktopApp:packageUberJarForCurrentOS :desktopApp:packageExe`

GitHub Actions performs the authoritative clean-runner build and artifact validation.

## Product rules

- Secount is a **personal software product project**, not a student project.
- Security-sensitive changes require regression tests.
- Secrets must never be written to logs or committed to source.
- Pairing/relay transport is untrusted and authenticated payloads must be verified before applying state.
- Preserve backward compatibility deliberately; document migrations when compatibility is removed.

## Release rules

- Android, Windows and JAR artifacts are generated by CI.
- Release artifacts receive SHA-256 checksums.
- Version metadata must remain consistent across Android, desktop and runtime update-check code.
- Debug builds must never be published as production releases.
